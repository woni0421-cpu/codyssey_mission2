# 🏢 프로젝트 기획서: 우리 건물 입주민 전용 커뮤니티 웹앱

## 1. 프로젝트 개요
- **프로젝트명:** 우리 건물 커뮤니티 (가칭)
- **플랫폼:** 반응형 웹 애플리케이션 (Mobile First, PC Full-width 지원)
- **기획 배경:** 같은 건물(아파트, 오피스텔 등)에 거주하는 입주민들 간의 소통, 나눔, 문제 해결(층간소음 등)을 돕기 위한 폐쇄형 로컬 커뮤니티의 필요성 대두.
- **개발 형태:** 프론트엔드 단일 HTML 파일 (HTML, CSS, Vanilla JS) 기반의 SPA(Single Page Application) 프로토타입.

---

## 2. 핵심 타겟 및 목적
- **핵심 타겟:** 동일한 건물에 거주하는 실제 입주민 (1인 가구, 가족 단위 모두 포함)
- **서비스 목적:** 
  1. 신뢰할 수 있는 입주민 간의 안전한 중고 거래 및 나눔
  2. 배달비 쉐어, 공동구매 등을 통한 경제적 이점 제공
  3. 분실물 찾기, 층간소음 등 건물 내 이슈의 원만한 해결

---

## 3. 주요 기능 명세 (Key Features)

### 3.1. 안전하고 효율적인 인증 시스템 (2-Track)
관리자의 승인 부담을 줄이면서도 외부인을 차단하기 위한 하이브리드 인증 도입.
- **세대 최초 가입자 (서류 인증):** 임대차 계약서 또는 관리비 고지서를 첨부하여 관리자의 최초 1회 승인을 받음.
- **가족/동거인 가입자 (초대 코드):** 이미 인증된 최초 가입자가 마이페이지에서 '초대 코드'를 발급하여 전달.
  - **보안 장치:** 초대 코드는 발급 후 24시간 동안만 유효하며, 세대당 발급 횟수 제한(예: 3회).
  - **연대 책임제:** 초대받은 사용자가 커뮤니티 규칙을 위반할 경우, 초대한 사용자도 함께 제재를 받는 강력한 페널티 시스템 적용.

### 3.2. 홈 화면 및 카테고리 (2x4 그리드)
직관적인 이모티콘과 함께 8개의 카테고리를 2줄 x 4칸으로 고정 배열.
1. 🗣️ 자유게시판
2. 🔍 분실물
3. 🤝 장터/나눔
4. 🤲 빌려주세요
5. 📦 공동구매
6. 🛵 배달 같이
7. 🤫 층간소음
8. 📋 전체보기

### 3.3. 게시판 및 글쓰기 시스템
- **익명 시스템 제한적 허용:** 기본적으로 익명 글쓰기를 지원하여 층간소음 등의 민감한 이슈를 편하게 작성 가능.
- **장터/나눔 익명 불가:** 금전이 오가거나 대면이 필요한 '장터/나눔' 카테고리는 신뢰도를 위해 익명 작성을 시스템적으로 차단.
- **유효성 검사 (Validation):** 제목이나 내용에 띄어쓰기(공백)만 입력하고 등록하는 것을 방지 (`trim()` 함수 적용).

### 3.4. 1:1 채팅 기능
- 게시글 상세 페이지에서 작성자에게 바로 1:1 채팅 요청 가능.
- **채팅 목록 UI:** 화면이 확장되어도 읽기 편하도록 가로로 긴 1단 리스트 형태 유지.
- 실시간 대화창 UI (말풍선 형태, 본인 우측/상대방 좌측 정렬).

### 3.5. 실시간 알림 (Notification)
- 우측 상단 종 모양(🔔) 아이콘과 Red Dot(배지)을 통한 알림 인지.
- 클릭 시 드롭다운 패널 형태로 최신 알림 목록 제공.
- **알림 발생 조건:** 내 글에 새로운 댓글이 달렸을 때, 관리자 승인이 완료되었을 때 등.

## 4. UI/UX 및 반응형 디자인 (Responsive Web)

### 4.1. Mobile First 디자인
- 하단 네비게이션 바(홈, 채팅, 마이페이지)를 통한 손쉬운 탭 이동.
- 우측 하단 플로팅 액션 버튼(FAB)을 배치하여 언제든 빠른 글쓰기 진입 가능.

### 4.2. PC/태블릿 확장 (Full-width UI)
- `max-width` 제한을 해제하여 브라우저 창 크기에 맞춰 좌우 여백 없이 100% 꽉 차는 시원한 레이아웃 적용.
- **게시글 목록 자동 확장:** 화면이 넓어짐에 따라 빈 공간이 남지 않도록 CSS Grid(`auto-fill`)를 활용하여 게시글 카드가 자동으로 2단, 3단, 4단으로 늘어남.
- **채팅 목록 고정:** 채팅 목록은 시선의 분산을 막기 위해 화면이 넓어져도 1단 세로 배열을 유지.

## 5. 향후 발전 방향 (Next Steps)
현재는 프론트엔드 단일 파일로 구성된 프로토타입(Prototype) 단계이며, 실제 서비스 런칭을 위해 다음과 같은 후속 개발이 필요함.
1. **백엔드 연동:** Node.js, Spring Boot 등을 활용한 REST API 서버 구축.
2. **데이터베이스(DB):** MySQL, MongoDB 등을 활용한 회원 정보, 게시글, 채팅 내역 영구 저장.
3. **웹소켓(WebSocket):** 1:1 채팅 및 알림 기능의 실시간(Real-time) 통신 구현.
4. **이미지 업로드:** AWS S3 등을 활용한 게시글 내 다중 이미지 첨부 기능.
